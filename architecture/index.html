Control VM

  • FastAPI: 이전 생성, 상태 조회, 컷오버 요청 접수. 긴 작업은 202 Accepted와 작업 ID만 반환
  • Migration Worker: 단계 실행. DB 복제 설정과 컷오버, rclone 실행, Cloudflare 가중치 변경
  • rclone: 오브젝트 전체 복사, SQS 이벤트 기반 증분 복사, 주기 동기화, 역방향 동기화, rclone check 비교를 모두 담당
  • 관리 DB: 단계, barrier ID, 설정 버전, 실행 결과, 마지막 오류 저장. 업무 DB와 분리
  • 대시보드: 현재 단계, 복제 지연, 원본에 남은 WAL, 객체 동기화 밀림, 컷오버 준비 상태

Features

  • 사전 점검: DB 버전, 논리 복제 설정, PK 없는 테이블, 권한, sequence 목록, PgBouncer를 우회하는 writer
  • DB 이전: POST /db-migrations, GET /db-migrations/{id}, POST /db-migrations/{id}/cutover
  • 오브젝트 이전: 전체 복사, 증분 동기화, 읽기 폴백 비율과 최종 차이 확인
  • 트래픽 전환: Cloudflare 가중치 카나리와 즉시 되돌리기
  • 검증: 행 수와 해시 비교, 객체 차이 비교
  • 롤백: 대상 쓰기를 열기 전까지 자동. 이후는 수동 절차

Placement

  • PgBouncer는 마지막에 AWS를 지워도 남도록 GCP에 둔다. 컷오버 전에는 AWS 앱이 GCP를 거쳐 RDS로 가므로 두 클라우드를 같은 도시 리전에 둔다. 예: AWS ap-northeast-1, GCP asia-northeast1
  • PgBouncer와 제어 VM은 분리한다. 제어 서비스가 멈춰도 앱의 DB 트래픽은 계속 흘러야 한다
  • Cloud SQL은 RDS에 직접 접속해 변경을 받는다. HA VPN을 우선 쓰고, 시간이 부족하면 공인 IP, TLS, IP 허용 목록으로 시작한다
  • 별도 메시지 큐는 두지 않는다. DB 변경은 WAL과 복제 슬롯이 보관하고, Worker는 관리 DB의 작업 상태를 읽어 진행한다
  • 오브젝트는 rclone을 거쳐 제어 VM을 지나간다. 처리량 상한은 VM 네트워크 대역폭이다

Out of scope

  • PostgreSQL 외 엔진, Azure
  • 자동 역방향 DB 복제
  • PgBouncer 고가용성
  • 온프렘 에이전트. 제품에서는 PgBouncer와 Worker, rclone이 고객 네트워크에 설치되는 에이전트가 된다
