이전 플랫폼 아키텍처

유저 앱이 AWS, GCP, 온프렘 중 어디에 있든 같은 설정으로 돌게 하고, 그 아래의 DB, Redis, 오브젝트 스토리지를 서비스를 멈추지 않고 다른 클라우드로 옮깁니다. 이 페이지는 이전을 수행하는 플랫폼 앱의 구성입니다. 각 저장소의 이전 방식은 서비스별 설계 문서에 있습니다.

정한 것

리전서울AWS ap-northeast-2, GCP asia-northeast3. 플랫폼과 모든 시험을 서울에서.
플랫폼 위치AWS 관리 VPC 하나오케스트레이터, 이전 서버, 프록시를 모두 10.30.0.0/16에. 플랫폼은 이전 대상이 아님.
들어오는 길Cloudflare LB + Tunnel모든 VM에 인바운드 포트 없음. 환경별 비율은 LB 가중치로.
클라우드 사이TailscaleVPC마다 서브넷 라우터 하나. 사설 주소가 겹치지 않게 대역을 나눔.
상태 저장서비스마다 따로공유 DB 없음. 오케스트레이터, DB, 오브젝트는 각자 DynamoDB 테이블, Redis는 EFS.
제어 방식공통 API 초안 0.2오케스트레이터가 모든 이전 서버를 같은 actions·operations 계약으로 부름.

전체 구성

유저 앱의 요청 경로

유저 앱은 저장소 주소를 세 개만 압니다. 이전 중에 그 주소는 바뀌지 않고, 주소 뒤에서 가리키는 곳만 바뀝니다. 그래서 앱은 어느 환경에 떠 있든 같은 설정으로 돕니다.

이전 순서

복제는 한꺼번에 걸어도 사용자에게 영향이 없지만, 전환은 한 번에 하나씩 합니다. 단계마다 넘어가는 조건을 숫자로 정해 두고, 맞지 않으면 그 단계만 되돌립니다. AWS에서 GCP로 옮기는 예입니다.

네트워크

Tailscale 서브넷 라우터가 모든 VPC를 하나의 주소 공간으로 묶으므로 대역이 겹치면 안 됩니다. traffic 설계의 대역 계획을 그대로 쓰고, IaC 초안을 여기에 맞춥니다.

  • 인바운드 포트 없음. 모든 VM은 바깥으로만 연결합니다(cloudflared 7844·443, Tailscale). IaC 초안의 80/443 개방은 뺍니다.
  • 서브넷 라우터는 앱 VM이 겸합니다. AWS EC2는 source/dest check를 끄고, GCE는 IP forwarding을 켭니다. 관리 VPC는 게이트웨이 EC2가 맡고, 사설 서브넷 라우트 표가 다른 대역을 그 EC2로 보냅니다.
  • 이름은 *.internal로 고정합니다. Route 53 사설 영역이 내부 NLB를 가리키고, GCP와 온프렘은 Tailscale split DNS로 Route 53 Resolver 인바운드 엔드포인트에 묻습니다.
  • RDS → Cloud SQL 복제만 Tailscale을 타지 않습니다. 관리형끼리라 Tailscale을 설치할 수 없어서, RDS 공인 엔드포인트에 TLS를 걸고 DMS의 공인 IP만 허용합니다.
  • 비밀값은 Secrets Manager에만 둡니다. Tunnel 토큰, Tailscale 인증 키, 각 클라우드 자격 증명을 Terraform 변수나 초기화 스크립트에 넣지 않습니다.

플랫폼이 AWS 밖에 만드는 것

플랫폼 앱은 AWS 관리 VPC에서만 돕니다. 다만 GCP 서비스를 써야 하는 두 가지는 GCP 프로젝트에 생깁니다. 둘 다 플랫폼이 AWS에서 만들고 지웁니다.

  • DMS 이전 작업: GCP 서비스라 GCP 프로젝트에 생깁니다. DB 이전 서버가 API로 만들고 promote합니다.
  • Pub/Sub 토픽: GCS 버킷의 변경 알림은 Pub/Sub로만 나옵니다. 오브젝트 이전 서버가 토픽과 구독을 만들고, 이전이 끝나면 지웁니다.

감수하는 것과 남은 문제

  • 이전이 끝나도 DB와 Redis 요청은 AWS를 지납니다. 프록시가 관리 VPC에 있어서, GCP로 다 옮긴 뒤에도 GCP 앱 → 서울 AWS → GCP 저장소로 갑니다. 플랫폼을 AWS 하나에 두기로 한 대가입니다. 같은 서울이라 왕복이 몇 ms일 것으로 보지만 아직 재지 않았습니다.
  • DB 롤백은 대상에 쓰기가 시작되기 전까지만 됩니다. DMS에 역방향 복제가 없습니다. 4단계에서 쓰기를 재개한 뒤 문제가 나면 앞으로 고치는 수밖에 없습니다.
  • DB 이전 서버가 오케스트레이터에게 자기 DynamoDB에 정지 근거를 직접 쓰라고 요구합니다. 서비스마다 저장소를 따로 둔다는 원칙과 맞지 않아, quiesceRef를 API로 넘기는 방식으로 맞추자고 제안할 예정입니다.
  • PgBouncer가 지금은 공인 DNS로 열려 있습니다. 이 그림대로 내부 NLB와 db-proxy.internal로 옮겨야 합니다.
  • 유저 앱의 오브젝트 모듈(objroute.py)에 삭제 기록이 없습니다. 이대로면 전환 중에 지운 객체가 복사로 되살아날 수 있습니다.
  • 대상 환경에 유저 앱을 띄우는 담당이 없습니다. 공통 문서의 COMPUTE 범위인데 맡은 서버가 없습니다.
  • 인프라는 아직 그림입니다. IaC는 한 번도 적용하지 않았고 관리 VPC 정의가 없습니다. traffic은 설계만 있습니다. 오브젝트 실측은 도쿄에서 했으므로 서울에서 다시 합니다.
